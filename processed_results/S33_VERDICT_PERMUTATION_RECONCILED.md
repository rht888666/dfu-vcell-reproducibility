# S33 VERDICT — 置换检验口径统一（遗留问题闭合）

**日期**：2026-10-06 (R15 续)
**背景**：S32 数字审计发现同一检验（Healer − NonHealer, raw progress score）在两个脚本中给出不同 p：
`S24b_state_model.json` → p = 0.0245；`S25b_scheme_comparison.json` → p = 0.0257。

---

## 一、根因诊断（已核实）

| 脚本 | 随机源 | nperm | 检验 |
|---|---|---|---|
| `S24b_state_model_robust.py` | 模块级 `RNG = default_rng(20261006)`，**被前面多个检验消耗过状态** | 10,000 | 单侧，Healer > NonHealer |
| `S25b_overcorrection.py` | `perm_test(..., seed=11)`，**独立全新 rng** | 10,000 | 同上 |

**检验逻辑完全相同**（单侧、nperm=10000、`(cnt+1)/(nperm+1)`）。
差异**纯粹来自随机数流起点不同** → 属正常 Monte Carlo 波动，**不是方法学错误，也不是数据不一致**。

**量级合理性**：n = 14（9 vs 5），可得的最小 p 为 1/10001 ≈ 0.0001；在两个独立随机流下
p ≈ 0.0245 与 0.0257 的差异（Δ = 0.0012）远小于该尺度，完全在 MC 噪声内。

---

## 二、处置决定

1. **不修改任何脚本**（两者的检验都是正确的，改任一都无必要）。
2. **稿件统一采用 S25b 的值（p = 0.025）**，理由：S25b 是深度方案矩阵的**主分析脚本**，
   稿件 Table 5 与 §2.5 的其他数字全部来自 S25b，保持单一来源可复现性最强。
3. **在 Methods 中明确声明该检验的可复现参数**（单侧、10,000 次、Healer > NonHealer）。
4. **稿件 Table 5 raw 行**已改为 `+0.341 / 0.025 / +0.613`。

---

## 三、对结论的影响

**无影响**。无论 p = 0.0245 还是 0.0257：
- 仍小于 0.05 → "naive score 显著"
- 仍被深度混淆（ρ = +0.613）
- 结论仍是"不成立，是深度伪影"

该差异**不构成任何主张的边界**，记录在案是为了**可复现性透明**，不是为了修正结论。
